# 实验室生产环境接管与自动化任务清单

适用范围：实验室原有 Windows 控制电脑、GPIB-USB 控制器、Keithley 2182A、6221、2450，以及现有 LabVIEW 工程。第一天的目标是**理解并保存现状，建立可复现的只读基线**，不是替换 LabVIEW，也不是让 Python 接管测量。

## 一、不可突破的边界

- [ ] Mac 只用于生成、审查、模拟和打包代码；不连接真实 GPIB。
- [ ] 只有实验室那台已经实际控制过仪器的 Windows 64 位电脑可以运行真实模式。
- [ ] 未确认当天没有实验正在运行前，不打开 VISA 会话、不拔线、不关闭 LabVIEW。
- [ ] 未完成环境盘点和备份前，不升级或卸载 Windows、LabVIEW、NI-VISA、NI-488.2、仪器驱动和固件。
- [ ] 不改变 GPIB 地址、2450 Command Set、串口参数、LAN 设置或仪器面板设置。
- [ ] 不点击 NI MAX/VISAIC 的 Reset、Clear、Self Test；不运行含输出控制的旧主 VI 做首次测试。
- [ ] 不发送 `*RST`、`*CLS`、输出开关、源值、触发、校准、保存/调用配置、清缓冲等命令。
- [ ] 每次生产操作使用新的时间戳目录；原始日志只追加和复制，不覆盖。
- [ ] 出现未知状态时停止并记录，不用“试一试”的写命令修复。

## 二、今晚在 Mac 上完成

- [ ] 保留项目完整文件夹 `readonly_instrument_probe`，不要只复制单个 Python 文件。
- [ ] 在 Mac 运行全部安全测试和四个 profile 的模拟测试。
- [ ] 阅读程序计划：2182A、6221、2450-SCPI、2450-TSP 的 `--show-plan` 输出。
- [ ] 准备实验室允许使用的传输方式（受控 U 盘、校内网盘或实验室共享盘）。
- [ ] 准备相机或手机、纸笔、线缆标签；如要记录环境，准备已校准温湿度计。
- [ ] 确认可以联系现有 LabVIEW 操作者或实验负责人。
- [ ] 不在 Mac 安装 NI 驱动来替代实验室生产环境；Mac 模拟通过不代表 GPIB 已通过。

## 七、部署 Python 探针（不污染现有工程）

建议独立目录：`C:\LabAutomation\readonly_instrument_probe-0.5.0`。不要放进 LabVIEW 工程目录，不要使用会自动同步的文件夹。

- [ ] 将完整项目复制到版本化目录。
- [ ] 先运行 `python --version`、`py --list-paths`、`where.exe python`，记录全部现有 Python 的版本、路径和位数。
- [ ] Python 3.9+ 可作为候选；不覆盖其他程序正在依赖的旧 Python。没有合适版本时先取得并行安装许可。
- [ ] 创建项目独立虚拟环境 `.venv`。
- [ ] 有网时安装项目和 PyVISA；无网时使用事先审批并校验哈希的 Windows 离线 wheel。
- [ ] 沿用现有 NI-VISA；不默认安装另一 VISA backend，不替换系统 NI 驱动。
- [ ] 不凭 Python 位数推断可用性；用 PyVISA 资源枚举验证 Python 与 NI-VISA 位数是否实际匹配。
- [ ] 运行单元测试，保存屏幕结果。
- [ ] 运行 `--audit-host`，确认四个检查均为 `true`。
- [ ] 若 Python、驱动或权限安装失败，当天仍可完成环境盘点；不要仓促改生产系统。

PowerShell 初始命令见 `DEBUG_TUTORIAL_zh.md`。

## 十、逐级只读验证

### A. 零消息阶段

- [ ] `--audit-host`：只审计电脑。
- [ ] `--list-lab-addresses`：只显示代码中的 NI MAX 确认地址。
- [ ] `--show-plan`：只显示各 profile 白名单。
- [ ] `--list-visa-resources`：让 VISA 枚举资源，不向仪器发送消息。
- [ ] 对比 NI MAX 中看到的资源名；不要点击 Reset/Clear。

### B. 身份阶段

- [ ] `--identify-lab`：对六个确认地址分别只发送一次 `*IDN?`。
- [ ] 保存制造商、型号、序列号、固件和地址对应关系。
- [ ] 无设备的地址超时可以记录为失败，不因此修改任何仪器地址。
- [ ] 发现未知设备、重复地址或型号不符时停止。

### C. 单机 identity 阶段

- [ ] 使用已确认的真实地址，一次只验证一台仪器。
- [ ] 先 2182A，再 6221，最后 2450；若实验室 SOP 有不同顺序，以 SOP 为准并记录。
- [ ] 2450 身份成功后，从面板/原 VI 证据确认 SCPI 或 TSP，不由程序切换。

### D. core 阶段

- [ ] 只有 identity 全部通过后才运行 `--scope core`。
- [ ] 每台仪器完成后先检查 JSON，再进入下一台。
- [ ] 任何通信错误、型号不匹配或意外状态立即停止。

### E. full 阶段

- [ ] 第一天不必完成。只有 core 结果与手册、面板和原 VI 一致后，才选一台运行 full。
- [ ] full 仍是查询白名单，但查询面更广；不能把它理解为“读取所有内存”。

## 十五、走向自动化的阶段路线

### 阶段 0：只读基线（当前）

固定物理拓扑、版本、地址、命令集、参数和日志格式。至少重复多次得到一致结果，再讨论控制。

### 阶段 1：回放与数字替身

用脱敏 JSON 和模拟器复现成功、超时、型号不符、断线等场景。自动化逻辑先对模拟环境运行，不接仪器。

### 阶段 2：定义受控写操作（仍不在生产执行）

逐条写出未来需要的设置、合法范围、单位、前置条件、联锁、超时、回读确认、失败回滚和批准人。禁止开放任意 SCPI `write()` 接口。

### 阶段 3：非生产台架验收

使用备用仪器、假负载/限流保护和可接受风险的样品，验证输出上限、紧急停止、断线和断电恢复。形成可签字的验收记录。

### 阶段 4：生产影子模式

Python 只观察并生成“计划执行内容”，由人工与现有 LabVIEW 结果比较，不向仪器写入。累计足够一致性证据。

### 阶段 5：受监督自动化

经负责人批准后，按最小功能逐项开放；必须包含双重确认、硬件上限、状态回读、完整审计日志、急停、恢复 SOP 和可回退到原 LabVIEW 的方案。

### 阶段 6：正式运行与变更管理

锁定代码、配置、驱动、固件和校准版本；每次变更先在模拟/台架回归，再审批上线。定期测试备份恢复、急停、地址漂移和设备更换流程。

自动化是否“成功”不能只看能否通信；至少还要证明结果正确、故障安全、可追溯、可重复、可恢复，并由实验负责人批准。
